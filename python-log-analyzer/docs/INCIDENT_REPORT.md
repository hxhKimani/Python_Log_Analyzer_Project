# Sample authentication investigation

## Scope

Offline analysis of the included synthetic CSV, using the default thresholds:
5 failures, 3 distinct usernames, and an inclusive 300-second window.
All timestamps below are UTC. These are generated training records.

## Findings

- `203.0.113.50` produced five failures for `admin` from 14:01:00 to 14:03:00
  (CSV lines 3–7). The fifth failure triggered REPEATED_FAILURES.
- A successful login for the same source and username at 14:03:30 (line 8)
  triggered SUCCESS_AFTER_FAILURES. Five preceding failures are attached as evidence.
- `198.51.100.20` failed against `alex`, `jordan`, and `taylor` from 14:04:00
  to 14:04:40 (lines 9–11), triggering MULTIPLE_ACCOUNTS_TARGETED.
- `192.0.2.10` had one failed login followed by a success for `lance`.
  This did not meet the configured failure threshold.

## Assessment and follow-up

The admin sequence warrants investigation, but the CSV alone cannot distinguish
an unauthorized login from a user retrying a password. The multi-account sequence
is consistent with account targeting but does not establish password spraying.

In a real investigation, validate the log source and event timestamps, identify
whether the source is shared infrastructure, and check with the account owner.
Correlate available MFA, endpoint, session, and application activity before drawing
a conclusion. Any containment would follow the organization's response process.
The analyzer performs no containment actions.

## Evidence limitations

No destination host, session ID, MFA outcome, account ownership, or password data is
included. Alerts are generated by simple heuristics from one synthetic data source.
